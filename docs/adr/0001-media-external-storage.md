# ADR-0001 — Медиа во внешнем хранилище, не self-host с VPS

**Статус:** Accepted · **амендмент 2026-09-01:** провайдер — Yandex Object Storage через штатный `@payloadcms/storage-s3`, **не** Я.Диск с самописными хуками (см. «Решение», п. 1)
**Дата:** 2026-06-03
**Контекст веха:** M1 → M3

## Контекст

Сайт фестиваля в пик сезона (июнь-июль) отдаёт фото и видео. Прод-бокс — небольшой облачный, единицы vCPU и гигабайт. Отдавать тяжёлое видео и крупные галереи напрямую с такого сервера в пик = риск исчерпать канал/диск и уронить сайт ровно тогда, когда он нужен.

Соседний проект GONBA уже решил это: медиа синхронизируются на Яндекс.Диск, а отдача идёт через прокси/публичные ссылки (см. `../brain_matrica/cross-project-ideas/REFERENCE.md` R2, и GONBA `web/src/collections/Media.ts`).

## Решение

1. **Фото → внешнее хранилище.** ~~Приём GONBA (Я.Диск) с хуками `afterChange`/`afterRead` и прокси-эндпоинтом~~ — **заменено 2026-09-01:** тот же бакет Object Storage, что уже год обслуживает UGC, через штатный адаптер `@payloadcms/storage-s3@3.75.0` с `disablePayloadAccessControl` — `url` записи указывает прямо на бакет, бокс не хранит и не проксирует ни байта.
   *Почему не Я.Диск:* консьюмерский API с лимитами на публичные ссылки, вторая интеграция без ключей и адаптера, и — главное — любая схема «подкачать на прод и кэшировать» возвращает бокс в путь данных, а срок жизни кэша не ограничивает диск (ограничивает только потолок по объёму с LRU). *Почему без `prefix`:* поля `url`/`sizes.*.url` в схеме уже есть, `prefix` добавил бы колонку → миграция (G192).
   *Факты, на которых решение:* замер 01.09 — media 1.4 ГБ / 2159 файлов, 76 % объёма — 588 оригиналов фотостены (холодные), но оригиналы дают 51 % байт медиа-трафика (8.3 ГБ за квартал с бокса). Миграция уносит и хранение, и отдачу. Порядок: `sync-media-to-s3.yml` (файлы в бакете) → мерж адаптера; наоборот — битые картинки.
2. **Видео → встраивание плеером** (Rutube/VK), а не загрузка файлов в Payload. В `Gallery.videos[]` хранится только ссылка-embed.
3. **MVP (сейчас):** коллекция `Media` использует локальный `staticDir` (`web/public/media/`, в `.gitignore`). Это временно — до подключения внешнего хранилища (M3). Каркас намеренно оставлен простым, чтобы не тащить интеграцию Я.Диска до того, как поднят прод.

## Последствия

- В `web/next.config.js` уже разрешены remote-хосты `disk.yandex.ru` / `downloader.disk.yandex.ru` для `next/image`.
- При подключении внешнего хранилища: добавить поля синхронизации в `Media` (по образцу GONBA — `yandexPath`, `yandexPublicUrl`, …), хук заливки, прокси-эндпоинт `/api/media/file/[id]`. Это **второй потребитель** паттерна Payload+Media→Я.Диск → повод промотировать REFERENCE R2/R3 в полноценный pool (письмо в `mailbox/to-brain/`).
- Грабли миграций Payload при добавлении полей — см. GOTCHAS G7 (`_v`-таблицы версионируемых коллекций).
