## Грабли, которые дороже всего забыть

- **Миграция схемы = три файла `.ts` + `.sql` + `.json`** (G192). Снапшота нет → drizzle диффит против пустоты → `down()` с `DROP TABLE … CASCADE` по всем таблицам. Отдельно: **initial-миграции у нас нет**, цепочка схему с нуля не воспроизводит; правда о схеме = конфиг + прод, сверка — `probe-schema.yml`. Детали: [`web/src/migrations/README.md`](../web/src/migrations/README.md).
- **PR-CI теперь ЕСТЬ** (`gates.yml`: с 2026-08-10 typecheck · lint · приёмка клиента vault, с 2026-08-31 **сканер секретов первым шагом**) — прежняя памятка «`gh pr checks` всегда пустой, гейт только локальный» устарела. Job называется `gates`, он **required-контекст `main` с `enforce_admins`** — то есть красный реально не даёт смержить. `build` с Postgres по-прежнему после мержа, в `deploy-prod`. `lint` гоняется с `--max-warnings 0`: без этого `next lint` отдаёт exit 0 при предупреждениях.
- **Сканер валит job по ИСТОРИИ ветки, а не по рабочему дереву.** Поймал строку → правка следующим коммитом **не помогает**, красный остаётся: `fetch-depth: 0` и `gitleaks git` смотрят все коммиты. Лечится пересборкой ветки (`git reset --soft origin/main` → один чистый коммит → новая ветка, т.к. force-push запрещён). Поймано на себе 31.08: гейт уронил письмо-отчёт о самом гейте, потому что оно цитировало строку дословно.
- **Ложный красный сканера лечить формой, а не каталогом.** Дефолтное `generic-api-key` срабатывает на поля с именем `key` и слагом-значением в сидах. Соблазн «исключить путь сидов» — ловушка: именно в SQL-**сиде** у соседа лежал живой ВК-токен. Исключения в `.gitleaks.toml` — по точной форме строки + `targetRules`, никогда по каталогу.
- **Логи прогонов ПУБЛИЧНЫ, и раннер печатает весь текст `run:`-блока.** Значит фильтрация вывода не закрывает канал: литерал в скрипте попадёт в лог независимо. Маскируется только `secrets` (`vars` печатаются как есть). Любой фильтр принимать **прогоном по настоящему выводу** с пустым грепом — по модели проверять бесполезно, я на этом ошибся дважды подряд.
- **Прод с этой машины виден только браузерным инструментом** — node fetch/curl не резолвят наши .рф-хосты; «недоступен» из curl — ложный сигнал. Кириллица в curl → mojibake, для API-тестов брать node fetch.
- **Видимое имя шапки/футера/героя рендерится из БД-глобалов**, не из кода — правка кода их не меняет, нужен точечный апдейт БД (`apply-brand.yml`, ярус `ask`).
- **`payload run` виснет молча** при расхождении конфиг↔dev-БД (интерактивный DROP-промпт) → сиды гонять с `NODE_ENV=production`; `build` при живом dev-сервере падает на `/_not-found` → `rm -rf .next`.
- **MEDIA_DIR** обязателен любому воркфлоу, который пишет в Media, иначе файлы лягут в эфемерный чекаут, а приложение отдаёт из персистентного `shared/media` → битые картинки при целых записях.
