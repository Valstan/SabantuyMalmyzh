# Прод-бокс: что живёт вне git и как это устроено

Заметки о прод-боксе Сабантуя (Ubuntu 24.04), чтобы не переоткрывать это каждой
сессией. Всё ниже — **вне репозитория**: правкой кода не меняется.

> **Локаторы здесь не держим** (D-038, `AGENTS.md` §«Публичный репозиторий — тоже
> recon-поверхность»): адрес бокса, внешний порт, SSH-алиас, имя хостера, имена
> соседних проектов на боксе. Репозиторий публичный с 2026-08-17, и «в документах,
> а не на витрине» с этой даты не спасает. Ниже — **механика**, которая и есть
> ценное знание; адреса берутся из `secrets` репозитория воркфлоу.

## HTTPS и редирект http→https (директива brain 2026-07-12)

- **Сертификаты выдаёт панель хостинг-провайдера** (раздел SSL), а **не** `certbot`
  на боксе. На момент 2026-07-12 стояли сертификаты старого домена (с 28.05) и
  wildcard нового (с 28.06) — https 200 работал и до редиректа.
- **Редирект включён 2026-07-12** сессией соседнего проекта по решению владельца.
  Живёт в конфиге nginx вне git (бэкап оставлен рядом с суффиксом даты).
- Условие редиректа — **по заголовку `X-Forwarded-Proto`**, не по `$scheme`:

  ```nginx
  if ($http_x_forwarded_proto = "http") { return 301 https://$host$request_uri; }
  ```

  Внешние 80/443 терминирует прокси провайдера, внутрь **всегда** приходит `http` →
  условие на `$scheme` даёт бесконечную петлю. Грабля — G150 в библиотеке мозга
  ([`GOTCHAS.md`](../../../brain_matrica/cross-project-ideas/GOTCHAS.md)).
- **CI-смоуки не задеты:** `deploy-prod.yml` бьёт локальный порт приложения мимо
  nginx, а localhost без `X-Forwarded-Proto` не редиректится.
- 301 со старого домена на новый — по-прежнему наш `web/src/middleware.ts`
  (host-based, постранично), а не nginx.

## Бокс общий

Сабантуй на боксе не один: сессии соседних проектов могут править конфиги nginx.
При диагностике «сайт отдаёт не то» проверять, не менялся ли nginx-конф — листинг
каталога `conf.d` показывает и бэкапы, которые соседи оставляют рядом.

## Прочее, что вне git

| Что | Где | Кто пишет |
|---|---|---|
| Секреты приложения | env-файл сервиса под `/etc`, `root:0640` | воркфлоу `apply-*-secrets` (ярус `ask`) |
| Персистентная медиатека | каталог вне релиза, симлинком (`MEDIA_DIR`) | приложение + `recover-fotostena-media.yml` |
| systemd-юнит | юнит сервиса | настраивался при M3 |
| nginx | конфиг сайта в `conf.d` | вручную/соседи (см. выше) |

Точные пути — в самих воркфлоу (они их и применяют) и в комнате КАРМАНа.

Read-only диагностика бокса — `probe-prod.yml` (метрики/логи/диск) и
`probe-schema.yml` (инвентарь схемы БД). SSH напрямую с dev-машины режется
edge-фильтром провайдера (G8) — ходить воркфлоу с раннера.

⚠️ **Логи прогонов публичны.** Дампы `journalctl`/`systemctl status` несут хостнейм
в каждой строке, серверные пути в `Loaded:`, а ошибка подключения к БД — целую
строку подключения с паролем. Диагностический вывод фильтровать, и фильтр
принимать прогоном по настоящему выводу, а не по модели (#224).
