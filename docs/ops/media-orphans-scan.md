# Скан медиа-сирот — как читать и почему «0 сирот» ничего не значит

**Что это:** read-only проверка, какие файлы в `media` не используются ни одной страницей сайта.
**Как запустить:** `gh workflow run probe-media-orphans.yml` (ярус auto, только SELECT).
**Сканер:** [`.github/scripts/media-orphans-reference.sql`](../../.github/scripts/media-orphans-reference.sql).

## Что он обходит

1. **Все relation-колонки `*_id`** в схеме `public`, значение которых совпадает с `media.id` — без хардкода имён полей (Events, Gallery, News, Pages, VkCandidates, join-таблицы many-to-many).
2. **Все jsonb-колонки** — lexical-embed'ы вида `{"relationTo":"media","value":<id>}` (картинки внутри текстов).

## Чего он НЕ считает ссылкой (и это главное)

Внутренние таблицы Payload ссылаются на саму сущность:

| Таблица | Почему не ссылка |
|---|---|
| `_media_v.parent_id` | версии самой media: `parent_id` = её собственный `id` |
| `media_locales._parent_id` | локализация: `parent_id` = `id` родителя-media |
| `*_rels`, `payload_*`, `%_locales` | служебные связи Payload |

**Пока эти таблицы попадают в обход, скан называет связанными ВСЕ файлы и печатает «сирот: 0».** Это ложный ноль — он повторился у нас дважды, пока в отчёте не появился позитивный контроль.

## Позитивный контроль (обязателен)

Отчёт печатает три независимых числа. Они должны сходиться, иначе результату не верить:

```
referenced                 — сколько media найдено хотя бы одной ссылкой
not_referenced_by_columns   — сколько не найдено в *_id-колонках
orphans / truly_unreferenced — итог
```

Прогон 2026-10-02: `640 media · 483 связаны · 157 orphans (228 МБ)`, контроль `157 = 157 = 157`.

**Симптом-примет ложного нуля:** `orphans: 0`, но `not_referenced_by_columns > 0` — значит внутренние таблицы попали в счёт.

## Удаление (отдельный шаг, ярус `ask`)

Удаление медиа — мутация живых прод-данных. Порядок:
1. приёмка скана на **заведомо используемом** файле (он не должен попасть в список);
2. решение владельца;
3. удаление через Payload (`/api/media/<id>`) — он же сносит объект в S3 и все размеры.

Прямое удаление объектов в S3 в обход Payload **запрещено**: строка останется в БД и продолжит отдаваться.
