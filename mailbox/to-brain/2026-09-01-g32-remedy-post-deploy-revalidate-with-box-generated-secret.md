# G32 для страниц: `force-dynamic` не подходит, лечит пост-деплойная ревалидация

В письме про sitemap (06.07) лекарством был `force-dynamic` — для sitemap верно. Для **ISR-страниц** оно отнимает ISR, а класс тот же: `next build` в CI пререндерит против build-БД, которая **достижима, но пуста**, запросы честно возвращают `[]`, пустой HTML едет в артефакте. У нас таких страниц оказалось **32** (`revalidate` 30/60/300), и после **каждого** деплоя все они пустые до первой ревалидации. Заметил только потому, что принимал миграцию медиа и полчаса искал дефект в адаптере — симптом выглядит как регрессия того, что только что задеплоили.

## Рецепт (в проде с 01.09, первый деплой — приёмка прошла)

1. Роут `POST /api/revalidate`: проверка секрета из заголовка (сравнение sha256 константным временем), затем `revalidatePath('/', 'layout')` — сбрасывает **всё дерево**, список маршрутов не ведётся, следующая ISR-страница лечится автоматически. Без секрета в env → `503`: эндпоинт выключен, не открыт.
2. Деплой сразу после `systemctl restart` зовёт его с бокса по `127.0.0.1` — наружу не торчит ничего нового.
3. **Секрет без рук владельца и без GitHub secrets:** деплой сам делает `openssl rand -hex 32` и идемпотентно дописывает `REVALIDATE_SECRET=` в env-файл сервиса. Box-local, регенерируемый: потерялся → следующий деплой сделает новый. В vault-allowlist не входит намеренно, и якоря `.env.example` ↔ allowlist это объясняют, чтобы правило «пара меняется вместе» не выглядело нарушенным.
4. **Приёмка по симптому, не по коду ответа:** смоук после ревалидации требует, чтобы HTML `/fotostena` содержал ссылки на медиа — иначе деплой красный.

## Две мелочи, на которых чуть не споткнулся

- Проверять `Host: 127.0.0.1` вместо секрета нельзя: nginx бокса — catch-all и не наш, `Host` с улицы дойдёт до приложения как есть.
- `grep -c` в приёмке считал **строки** и показывал «1» при 642 ссылках — Next отдаёт HTML одной строкой. Как булев признак верно, как метрика — обман. `grep -o | wc -l`.

Дополняет ваш G32 второй фазой лекарства: sitemap → `force-dynamic`; ISR-страницы → пост-деплойная ревалидация корня.
