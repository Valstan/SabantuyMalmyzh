# D-093 — три вещи, все на месте

PR #328, деплой 35647700326, ключ на боксе — прогон 35648052001.

1. **Маршрут.** `POST /api/ingest/posts`, заголовок `X-Gateway-Key` (или `Bearer`), тело по контракту портала и Казанской: `{vkPostId, sourceUrl, title?, text?, section?|rubric?, date?, images?, videos?, publishedAt?, publish?}`. Проба с бокса после записи ключа: **без ключа → 401**. Идемпотентность по `vkPostId` (unique-индекс в БД), **черновик по умолчанию**; `publish` принимается только с `X-Publish-Key`, а `INGEST_PUBLISH_KEY` не выдан — публикует человек. Повтор того же `vkPostId`: черновик обновляется, опубликованное не трогается (G320 учтён: поиск без `draft: true`).
2. **Ключ.** `INGEST_GATEWAY_KEY` в комнате `sabantuymalmyzh` (зеркало деплоя), grant → `setka` **предложен: 201, alias `SABANTUY_INGEST_KEY`**, note «D-093, brain 2026-09-15». Двусторонний путь КАРМАНа: принимает Сарафан своим токеном по allowlist имён. Повторный деплой grant не дублирует (`GET /grants` перед `POST`).
3. **Рубрики.** Одна: **`news`**. Владелец сказал «в ленту новостей», второго раздела у ленты нет, поле `rubric` в коллекцию не заводили. Классификатору хватит константы; пришлёт что-то другое в `section`/`rubric` — в ответе будет `warnings: ["unknown rubric: …"]`, пост всё равно ляжет черновиком.

## Что отличается от Казанской (только форма документа, не контракт)

- Коллекция `news`, не `posts`; группа `source {vkPostId, sourceUrl}` та же.
- Видео идут в наш массив `videos` (страница новости рендерит его плеером), а не link-узлами в текст.
- Галереи нет: первое изображение — обложка, остальные — `upload`-узлы между абзацами. Анонс в ленте — первый абзац текста.
- Атрибуция на странице новости — строка «Источник: ВКонтакте» ссылкой на оригинал.
