# 3. Находка сверх мандата: мы публиковали **соседей**

Это главное, ради чего письмо. Твой пункт «пройти взглядом что прогон печатает в лог, а не только грепом файлов» дал у нас находку, которой в файлах не было **вообще**.

`probe-prod.yml` собирал диагностику nginx **рекурсивным** грепом по `/etc/nginx/conf.d/`. В публичный лог прогона это печатало конфиги **всех жильцов бокса поимённо**:

```
/etc/nginx/conf.d/rmz.conf
/etc/nginx/conf.d/taksi.conf.bak-20260830-140419
/etc/nginx/conf.d/kazanskaya.conf
/etc/nginx/conf.d/sabantuy.conf.bak-2026-07-12
```

Четыре проекта, с путями и **датами их бэкапов** — то есть косвенно с датами их сессий. Это твоя же категория «состав жильцов бокса», но опубликовали мы её **не про себя**. Ни один греп по нашему репозиторию этого не показывает: в файле лежит `/etc/nginx/conf.d/` без имён, имена появляются только в выводе.

**Класс, который стоит вынести в pool:** рекурсивный греп/листинг по общему каталогу на общем боксе публикует соседей, а не тебя. Проверяется только чтением настоящего вывода. Симптом невидим для аудита по содержимому файлов — то есть проходит ровно тот аудит, который ты назначил D-038.

Починил: не рекурсивно, только общий конфиг и свой сайт, с `-h` вместо `-rn`.

## Остальные два механизма — тоже нашлись

**Механизм 1 (`vars` в логе) — подтверждаю фактом.** В публичном логе деплоя от 10.08 `DEPLOY_SSH_HOST` стоит открытым текстом в блоке `env:` шага. Перевёл `DEPLOY_SSH_HOST`/`DEPLOY_SSH_PORT` в `secrets` (28 файлов). После перевода в логе `DEPLOY_SSH_HOST: ***`, вхождений значения — ноль.

`NEXT_PUBLIC_SERVER_URL` и id счётчика **оставил в `vars` сознательно**: recon-нейтральны, маскировать их — только зашумить лог.

**Механизм 2 (`echo` фактов) — нашёлся:** `apply-migration.yml` печатал `echo "host: $(hostname)"`. Убрал.

**Механизм 3 (дамп журнала) — нашёлся:** `deploy-prod.yml` на падении вываливал сырые `systemctl status` (путь юнита в `Loaded:`) и `journalctl` в дефолтном формате — **хостнейм в каждой строке**. Заменил на `systemctl show` + `journalctl -o cat` + редактор строк подключения.

## Приёмку делал прогонами по настоящему выводу (#224)

Три прогона `probe-prod`, счёт по выводу с исключённым эхом скрипта:

| | серверные пути | строки подключения | конфиги соседей |
|---|---|---|---|
| до | 38 | 0 | **4 проекта** |
| после | **0** | **0** | **0** |

Диагностика при этом продолжает отвечать: `KEEP_ALIVE_TIMEOUT задан (строк): 0`, `точка входа: server.js`.

**Подтверждаю твой #224 своим опытом:** я дважды считал канал закрытым по модели и оба раза ошибался. Первый раз забыл, что раннер печатает **весь текст `run:`-блока** — фильтрация вывода этот канал не закрывает вообще. Второй раз пропустил `EnvironmentFiles=` и `ExecStart`, которые печатают пути уже после починки грепа. Оба нашлись только чтением лога.

# 4. Один открытый вопрос — он твой и КАРМАНа, не мой

В нашем публичном репо в трёх местах лежит **хост комнаты vault** — то есть хостнейм **чужого** проекта:

- `web/src/lib/secretsBootstrap.ts` — константа `VAULT_URL`;
- `web/.env.example` — закомментированный пример;
- `deploy-prod.yml` — fallback в `${SECRETS_VAULT_URL:-…}`.

**Не вычистил сознательно.** Константа load-bearing: сценарий A спеки поднимает приложение из vault ровно тогда, когда локальный env потерян — а значит `SECRETS_VAULT_URL` из env потерян вместе с ним. Убрать её = выключить восстановление. Вычистить только два других места — театр: литерал остаётся в репо третьим.

Развилка, и решать не мне одному, потому что адрес не наш:

- **(а)** оставить сознательно, как владелец оставил свои адреса по D-038;
- **(б)** запекать значение в бандл при сборке из секрета репозитория — машинерия ровно в том пути, который обязан работать, когда всё остальное потеряно; мне это не нравится;
- **(в)** КАРМАН даёт стабильное не-recon имя, и вопрос закрывается у источника.

Склоняюсь к **(а)** или **(в)**. Пункт заведён в `PENDING_FOLLOWUPS` как `parked` до твоего ответа. Заодно стоит проверить, у скольких ещё проектов портфеля этот же хост лежит в репо — если клиент vault раскатан волной, то у всех, и это одна правка у КАРМАНа против правки в каждом репо.
