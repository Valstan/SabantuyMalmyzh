# По строке на каждый пункт

## 1. Поле `pnpm` в `package.json` — не применимо, и проверка даёт ложное срабатывание

Ваш `grep -n '"pnpm"'` у нас попадает в **`engines`**, а не в конфиг:

```json
"engines": {
  "node": "^18.20.2 || >=20.9.0",
  "pnpm": "^9 || ^10"
},
"packageManager": "pnpm@10.15.0"
```

Это ограничение версии, pnpm его читает нормально — предупреждения
`The "pnpm" field in package.json is no longer read` в логах установки нет.

Конфиг уже там, где его читают: **`web/pnpm-workspace.yaml`** — `overrides:` (immutable, js-yaml, fast-uri, postcss, nanoid) и
`onlyBuiltDependencies:`. Приёмка по вашему же правилу пройдена: `pnpm install --frozen-lockfile`
(то, что делает CI) зелёный, переопределения в lockfile.

Отдельно, чтобы не смешивать: **`sharp` в overrides у нас нет** — находка `sharp < 0.35.5` из вашего письма 22.10
про аудит, а не про поле `pnpm`; ею займусь отдельной строкой.

**Поправка к памятке:** `grep '"pnpm"'` ловит `engines.pnpm` почти в любом проекте, который фиксирует версию
пакетного менеджера, — то есть даст «нашли» там, где всё в порядке. Точнее искать конфиг:
`grep -n -A3 '^[[:space:]]*"pnpm"[[:space:]]*:[[:space:]]*{' package.json` (объект, а не строка версии) или просто
`ls pnpm-workspace.yaml` и посмотреть, есть ли там `overrides`.

## 2. Порт приложения — уже на петле

Замер с бокса, 2026-11-01:

```
LISTEN 0 128      0.0.0.0:80       0.0.0.0:*
LISTEN 0 128    127.0.0.1:3000     0.0.0.0:*
LISTEN 0 128       [::]:80          [::]:*
```

- `127.0.0.1:3000` — **1**, wildcard-биндов на порту приложения — **0**;
- `HOSTNAME` в env-файле сервиса **задан** (одна строка), `PORT` тоже;
- `curl http://127.0.0.1:3000/` → **200**;
- запрос на порт приложения по публичному IP бокса → **отказ**, не 200.

То есть мимо nginx порт снаружи не отвечает: закрывать нечего, соседей не задеваем.

**Почему так вышло без отдельной починки:** standalone-сервер Next у нас стартует из systemd-юнита,
где `HOSTNAME` приезжает из env-файла, а не из шелла — то есть переменная есть всегда, а не «повезло,
что в этой сессии экспортировали».

Обе проверки закрыты, новых действий с нашей стороны не требуется.
