# Защитный хук: условие «кто» недостаточно, нужно ещё «откуда»

Класс из G194, у нас закрыт 2026-11-01 (PR #409). Записываю, потому что переносится на любой
Payload-проект и ломается молча.

## Форма

Служебные поля коллекции (статус модерации, счётчики, хеши владельца) пишет сервер. Клиент их
задавать не должен, и естественная защита — хук в `beforeValidate`, который **удаляет** их из
`data`, если `req.user` не персонал. Логика прозрачная, ревью проходит насквозь.

**Тот же признак ловит и наш собственный код.** У серверных пересчётов
(`recountViews`/`recountComments`/`recountReactionLikes`/`applyContentReport`) `req.user` тоже
нет — они зовут локальный API из хуков. Такой хук вычистит ровно то поле, ради которого они
существуют: **запись пройдёт, ошибки не будет, число просто не изменится**. Счётчик просмотров,
переставший расти на живом сайте, выглядит как «люди перестали заходить», а не как регрессия.

## Лечение

У Payload есть готовый дискриминатор источника: **`req.payloadAPI` = `'local' | 'REST' | 'GraphQL'`**.

```
if (req?.payloadAPI === 'local') return data        // наш код: хуки, роуты, сиды
if (isStaff(req.user)) return data                  // персонал из админки
// дальше — стричь: внешний запрос от не-персонала
```

Роуты, где посетитель меняет служебное поле по своим правилам (у нас «удалить свою публикацию»
ставит `status: 'removed'`), сами проверяют владельца ДО записи и зовут API **без** `req` — значит
остаются `local` и не ломаются. Проверять это при добавлении каждого нового роута: если он
передаёт `req` и при этом пишет служебное поле — хук его обрежет.

## Что закрепить

Тест на обе половины условия, иначе обе деградации беззвучны:

- **слишком широко** — умирают счётчики (ни исключения, ни кода ошибки);
- **слишком узко** — клиент подменяет статус публикации.

У нас это 7 кейсов в `stripPrivilegedFields.test.ts`: `REST`/`GraphQL` аноним и посетитель →
стёрто; персонал → сохранено; `local` → сохранено (в том числе `status: 'removed'` от
серверного роута).

Общая формулировка, которая шире этого случая: **фильтр по «кто» пропускает наш собственный код
как «никто»** — и стирает его работу. Если у операции есть два источника (снаружи и изнутри),
условие должно различать источник, а не пользователя.
