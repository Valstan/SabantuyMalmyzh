# Три находки, которые повторятся у любого Payload-проекта

Все три пойманы 02–03.10 при переносе 157 фото-сирот в альбом галереи. Общий знаменатель:
**симптом — «ничего не произошло, но никто не заметил»**. Ни одна из них не падает с ошибкой.

## 1. `payload run` завершает процесс сразу после загрузки модуля

`corepack pnpm -C web payload run src/seed/foo.ts` импортирует файл и, как только модуль
«оценил», выходит. Обёртка вида `main().then(...)` оставляет асинхронную работу в фоне →
**код 0, ни одной строки вывода**, скан отработал 10 с и «успешно» ничего не сделал.

Рабочий вид — top-level `await`:

```ts
const payload = await getPayload({ config })   // на верхнем уровне, без обёртки
```

Проверка дешёвая: локально `payload run <файл>` обязан напечатать хоть что-то после
`getPayload`. Стоит завести в `cross-project-ideas/GOTCHAS.md` — у нас это стоило трёх прогонов.

## 2. `payload run` глушит необрабоянное отклонение верхнего уровня

Симптом: `ELIFECYCLE Command failed with exit code 1`, **ни слова о причине**. `writeSync(2, …)`
не помогает — stderr дочернего `pnpm` в логе воркфлоу не виден.

Рецепт: тело сида под общим `try/catch`, причина через `payload.logger.info` + `err.cause`
(у ошибок Drizzle сообщение многострочное, обрезается).

## 3. Перевод литерала в `secrets.X` не создаёт секрет `X`

Рефакторинг D-038 заменил 21 копию `BASE=<путь на боксе>` на `secrets.DEPLOY_BASE`.
Секрета с таким именем в репозитории **не было**. GitHub подставил пустую строку, и все
воркфлоу, печатающие на бокс, стали падать (деплой, сиды, VK-конвейер, модерация, S3-синхронизация).
Чинится проверкой `gh secret list` **до** мержа и одним прогоном воркфлои глазами:
в логе должно быть `BASE=/…`, а не `BASE=`.

Общий класс, который мне стоит вынести отдельно: **операционные детали живут в трёх местах
одновременно** (файл воркфлоу, значение секрета, переменная/секрет у раннера). Рефакторинг
третьего без проверки первых двух ломает всё разом и тихо. Если у Мозга есть решение
(проверка «секрет непуст» как гейт в CI) — возьму с удовольствием.

## Смежное: Payload молча выбрасывает невалидные значения

`photos: [{ image, caption }]` (`type: 'array'` с блоком) получил от меня список id —
Payload **выбросил их без ошибки** и вернул успех; скрипт отрапортовал «готово», альбом не
изменился. Поймала только приёмка снаружи (`psql` показал 9 вместо 119).

Правило, которое стоит закрепить в pool: **после любой записи в коллекцию перечитывать её и
сравнивать с ожиданием**, а «готово» без такой сверки считать недоказанным. И: тип поля
брать из `src/collections/*.ts`, а не угадывать по join-таблице — `gallery_photos` выглядит
как hasMany, но это строки блоков.

## И ещё про temp-таблицы и пул соединений

`payload.db.drizzle.execute()` берёт **своё соединение** из пула на каждый вызов,
`CREATE TEMP TABLE` живёт в соединении. Блоки `DO $$ … EXCEPTION WHEN others THEN NULL`
это глушат, и скан «ссылок на медиа» честно отрапортовал **640 сирот из 640 файлов**
(то есть ноль собранных ссылок). Лечится одним запросом (`WITH ref AS (… UNION ALL …)`)
и стоп-контролем: «сироты == все файлы» → выход с ошибкой.

Про совпадение цифр: когда скан реализован в двух местах (psql и код), **расхождение — это
подсказка, а не шум**: у меня psql давал 157, JS-версия 315, и разница указала на блок
«все целочисленные колонки» (join-таблицы many-to-many), который есть в эталоне. Хорошо,
когда эталон — скрипт, а не вторая реализация.
